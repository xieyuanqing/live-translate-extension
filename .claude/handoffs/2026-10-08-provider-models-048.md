# 0.4.8：多模型目录、集中功能分配与提供商分类

## 当前方向

- 用户要求供应商只保存连接、凭据和可用模型，不在供应商卡片分配翻译用途。一套文字接口可以供不同功能选 Flash / Pro 等不同模型。
- 用户随后明确将所有设置页的接口／模型选择集中到第一个「API 与模型 → 功能分配」入口。各功能页保留当前绑定摘要和直达对应分配行的链接，删除重复选择器。
- 参考用户提供的生成页面，采用供应商类型快速筛选和更清楚的功能行层次；不照搬假延迟、假就绪状态、无效链接、外部字体／Tailwind 或未实现的功能。

## 已完成

- `providerSchema: 3`：文字提供商的 `models[]` 保存模型目录，五项文字功能各自保存 provider ID 与 model 字段；旧单模型配置迁入功能字段后不再持久化文字 provider.model。
- 「功能分配」是七项功能的唯一设置页选择器。实时音频、背景整理、整片字幕、聊天、评论、划词、朗读按侧栏功能顺序展示，显示真实填写／权限／生成测试状态。
- 功能页显示真实当前绑定、功能开关和行为参数，链接采用 `#models/purpose/{live,context,subs,chat,comment,selection,speech}`，进入后滚动并高亮对应行。
- API 提供商支持全部、实时翻译、文字模型、原文朗读筛选。筛选仅改变可见列表和编辑对象，不修改连接、启用状态或功能绑定；跨分类编辑、新增、复制、删除与排序保持可见目标。
- 文字模型目录支持获取、手动添加、移除和逐模型测试。添加提供商弹窗只显示已实现服务。划词浮窗可保存确切的 provider/model 对。
- 聊天可选 Chrome 本地翻译或云端文字接口；本地仍为默认。云端聊天分批请求、校验编号、按 provider/model 隔离缓存并取消旧请求。
- 文档和版本为 0.4.8。当前改动尚未提交或推送，原有未提交修改和附件均保留。
