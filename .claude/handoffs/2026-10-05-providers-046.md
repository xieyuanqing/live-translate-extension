# 0.4.6：按陪读蛙逻辑整理 API 提供商管理

日期：2026-10-05。用户指出 0.4.5 把“占位”理解错了：应在添加提供商的选择列表里放一两项，而不是设置页底部的开发计划卡。用户随后明确要求按陪读蛙 API 提供商设置页的整体交互逻辑实现。参考本机 Read Frog 的添加弹窗、配置列表、编辑器和功能分配源码，独立实现在本项目现有结构中。

## 本次结果

- API 提供商页的模型分类采用左侧配置列表、右侧单套编辑。添加入口打开原生分组弹窗：内置 LLM、兼容 API、纯翻译。DeepL / DeepLX 仅在这里置灰待接入，不能创建配置或调用。
- 去掉四块底部候选说明及冗余聊天接口页；旧 `#models/chat` 路由转到聊天功能页。直播和朗读仍使用原有类型专用连接配置，聊天仍为 Chrome 本地翻译。
- 配置保留固定 `preset` 身份，新增 `enabled` 和可选 `description`。旧配置按协议及地址识别，无法识别则保留同协议自定义类型；保留 Key、模型和各功能 id。
- 列表提供用途计数、启用开关和拖拽排序；移动端在当前编辑器中提供启用开关。被用途绑定的配置不能直接停用。未使用的配置停用后保留数据，但从功能选择中排除。
- 编辑器有名称、备注、Key 显隐、Base URL、模型组合框、查询/实际生成测试、功能用途开关、自定义请求头和高级请求参数。类型创建时确定，无额外协议下拉。
- 用途分配会启用目标配置，只替换对应功能 id；已分配用途不能直接关闭。复制独立模型配置，不复制用途绑定；删除被使用配置须有启用的替代项。添加、复制、启用、排序不会自动更换功能选用。
- 文字客户端拒绝停用配置；设置和划词下拉排除未绑定停用项，异常导入的停用绑定显示提示。保持请求快照、取消旧异步结果、请求头备份及脱敏行为。
- 版本、双 README、CHANGELOG 和开发说明同步 0.4.6，尚未发布。本轮未提交或推送 GitHub。
