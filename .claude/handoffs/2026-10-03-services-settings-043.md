# 0.4.3：服务入口与授权流程统一

## 用户选择和范围

- 用户认为设置页很乱，尤其外部 API 配置分散、域名授权藏在高级选项里；本地对照陪读蛙设置实现。
- 用户选择统一入口、布局和授权流程；继续保留直播、文字、朗读各自独立保存的配置。
- 工作区原本已有未提交的 0.4.1／0.4.2 划词浮窗、播放器图标等改动。本次保留这些改动，没有提交、推送或发布。

## 已完成

- `src/ui/options.html`：侧栏靠前增加「服务与接口」，沿用 `#models` 路由并细分 `/text`、`/live`、`/speech`。地址、Key、模型和授权集中在这里；直播／朗读功能页保留行为、音色、语速与试听，提供直达配置链接。
- 文字接口使用列表和单套编辑器；AI 整理、字幕翻译、划词翻译在上方独立选用。切换编辑对象、复制配置不会改变功能分配。删除正在使用的配置沿用现有回落行为。
- `src/ui/options-access.js`：共用授权控件紧挨地址，显示检查中／未授权／已授权／地址无效。请求权限在点击回调内直接发起；HTTP 权限按协议和主机匹配，省略端口。换地址后作废旧检查和授权结果；权限变更／窗口获得焦点时刷新。
- `options-providers.js`：查询、列模型、生成测试先授权，拒绝或授权期间换域名不会发送请求。查询接口与生成测试分开说明；高级项只保留并发和请求路径。
- `options-tts.js`：Gemini 试听也走共用授权；保留停止与供应商切换对迟到试听的取消保护。
- 千问仍请求既有 `<all_urls>` 权限，并明确说明握手认证与当前标签页／准确地址的临时规则；未改权限范围或运行时认证代码。Gemini Live 保留 WebSocket 路径。
- 深浅色与窄屏样式；三个功能选用桌面并排。数据字段未重命名，旧配置、Key、功能选用继续使用。
- 版本、两份 README、开发说明及 CHANGELOG 更新至 0.4.3（未发布）。
- `tools/preview.js` 显示离线预览标识、内存权限状态，并阻止实际 fetch。示例配置不进入运行包。
