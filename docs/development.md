## Audio and page lifecycle

`createMediaElementSource(video)` routes the element's audio through an AudioContext. Always preserve the source-to-destination connection so the original audio remains audible. Stop only the capture branch; do not close the shared context. Reuse each video's media source.

AudioWorklet is preferred, with ScriptProcessor as the existing fallback. The output is PCM16 little-endian, mono, 16 kHz: 1,600 samples / 3,200 bytes every 100 ms. Pausing, muting, and detected ads gate audio submission.

`start()` has several asynchronous waits. A session generation invalidates an old start after stop or navigation; AudioTap separately invalidates unfinished node attachment. Stale completion and error paths must not tear down a newer session.

Read video details through the page bridge and `getPlayerResponse()`. Navigation metadata must still match the current video before it can be used. Mount captions inside `#movie_player` so fullscreen and theater mode include them.

The branded controls are inserted as the first child of `#movie_player .ytp-right-controls`, alongside YouTube's native CC and Settings buttons. The Liuyi badge toggles caption visibility, and the adjacent play/stop button starts or cancels translation for the current mode. `main.js` retries mounting as YouTube builds or replaces the bar; if the bar is absent, no button is placed over the video. `liveCaptionsVisible` is an in-memory display preference combined with the advertisement gate; it does not stop AudioTap or the live client. Whole-video visibility delegates to `VideoSubsController.setVisible`, leaving translated cache data in place. Leaving a watch/live page keeps the existing behavior of stopping the session and removing player UI, including when YouTube continues playback in a cross-page mini player.

## Session configuration

Scenes contain a name and instruction and apply only to whole-video subtitle translation, with their existing storage preserved under its advanced Settings section. Live `Prompt.build()` no longer reads a scene: Gemini receives fixed translation rules plus generated or original session context, while Qwen receives target language and generated terminology. The popup merges temporary notes into the context viewer and replaces the scene statistic with the actual context/term status. Source and target language are separate settings. Persistent notes live in local storage; temporary notes live only in the content script's page memory.

Build the prompt once per session from the configuration read at startup. Reconnection and rotation reuse it. Appearance settings can update immediately; changing the translation configuration requires starting another session. If enabled and a text-model endpoint is configured, the live session makes one request before audio capture to summarize the video metadata into short context and up to 12 candidate terminology pairs. It resolves `liveContextProviderId` independently of the whole-video `subsProviderId`. `liveContextTimeoutSeconds` defaults to 60 and accepts 30, 60, or 120; the deadline is passed through `TextModel.translate` to the network layer and covers connection and the complete response, without an additional eight-second abort timer. Timeout errors identify the context request's deadline. Any failure falls back to the basic Gemini prompt or to Qwen without generated terminology. The generated text is treated as untrusted context, not as a proven accuracy improvement.

The popup's **本场提示词与术语** viewer queries a page-memory review separately from the compact status polling. **生成并预览** prepares the generator input/result and live configuration without mounting audio or starting a socket. The next start reuses it once only if settings, metadata, video, and temporary notes match. Settings/notes changes mark the preview stale; stop, start, and navigation invalidate pending previews so late results cannot overwrite another session. The current frozen review remains readable after stop on the same page. Configured keys are redacted before review data leaves the content script. The generator prioritizes streamer names and verified readings, and reserves a slot for an identifiable channel name without inventing aliases.

Appearance is delivered to the caption layer as CSS variables (`--lt-font-family`, `--lt-weight`, `--lt-color`, `--lt-source-color`, `--lt-source-scale`, plus the existing size, bottom, and opacity). `captionDisplayMode` (`bilingual`, `translationOnly`, `originalOnly`) and `captionTranslationPosition` are applied in `CaptionLayer.render()` only: they filter and order the lines and never stop a translation. The whole-video controller always passes the source text with each unit, so bilingual and original-only modes show the source before its translation arrives; live mode records input transcription unless the mode is translation-only. The Settings preview mounts the same `CaptionLayer` into a mock player, so it renders through the same path as the YouTube page. `subsExtraInstruction` is appended to the whole-video system prompt after the scene instruction and therefore changes the cache fingerprint.

The Settings page is split into hash-routed sections; the last visited section is remembered in `localStorage`. Settings are stored flat; `normalize()` clamps ranges and fills defaults and there is no migration between field layouts, so a renamed field simply falls back to its default.

`debugLogLevel` defaults to `off`; `basic` stores only connection, context-request result, capture/gate status, audio block counts, and elapsed times. `detailed` additionally stores video metadata, user notes, the exact Gemini prompt or Qwen terminology map, source transcriptions, translation fragments, and committed caption lines. The content script records these even when the display is translation-only. Each session has an independent `lt:live-log:<id>` record in `chrome.storage.local` with relative event times, an event cap of 3,000, and a dropped-event count. Writes are batched, serialized, and finalized on stop, navigation, or start failure. Only the latest 20 completed sessions are retained; active sessions are never pruned. Settings can export one or all logs as JSON and delete completed logs after confirmation. The recorder does not store PCM/audio payloads and redacts known configured keys plus common token formats, but exported text may still contain sensitive background information. Automated tests use fake storage and events; real browser shutdown durability remains unverified.

Page metadata and user background are wrapped as untrusted context, followed by a restatement of the translation task. This is a prompting strategy, not a security boundary with guaranteed model behavior.

Detailed logs additionally retain the generator input and Qwen terminology configuration; saved detailed sessions have a prompt viewer in Settings. Text/commit events include `videoMs`. Qwen includes connection generation, item/response/event identifiers, and output completion markers. `audio_sent` snapshots report cumulative successful socket sends, queue length, and chunks discarded due to queue bounds; they are separate from capture counts and do not prove upstream receipt. Socket closes record their code/reason. Qwen de-duplicates repeated protocol events/response completions with bounded identifier sets; its stabilizer disables guessed text overlap and sentence repetition suppression, and flushes residual text on output completion. Gemini keeps the previous stabilizer defaults.

The current UI labels are Chinese and some are also used in prompt composition. Before adding UI localization, separate presentation labels from stable prompt labels so a language toggle cannot silently change model instructions.

## Current Live setup

The following structure matches the existing implementation and earlier project tests. It is not a substitute for checking current service documentation and actual model access before changing the protocol.

```json
{
  "setup": {
    "model": "models/gemini-3.5-live-translate-preview",
    "generationConfig": {
      "responseModalities": ["AUDIO"],
      "translationConfig": {
        "targetLanguageCode": "zh",
        "echoTargetLanguage": true
      }
    },
    "inputAudioTranscription": {},
    "outputAudioTranscription": {},
    "systemInstruction": {
      "parts": [{ "text": "<frozen session prompt>" }]
    }
  }
}
```

The transcription fields are at setup level; `translationConfig` is inside `generationConfig`. Earlier project tests found these positions significant. `systemInstruction` in this translation mode is an experimental dependency based on observed behavior; do not promise strict instruction following or permanent support.

Audio chunks use `realtimeInput.audio`, a base64 payload, and MIME type `audio/pcm;rate=16000`. The extension reads transcription text and ignores generated audio.

The optional Qwen 3.8 mode connects to `wss://<workspace>.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime?model=qwen3.8-livetranslate-flash-realtime` (or the corresponding Singapore workspace). Its `session.update` asks for text output and passes the target language plus optional `translation.corpus.phrases`; audio uses `input_audio_buffer.append` with base64 PCM16 at 16 kHz. It emits input-transcription and `response.text` events. Qwen's current live protocol does not take a free-form `systemInstruction`, so scene text and the generated background cannot be applied there; only generated terminology pairs are sent.

Qwen requires `Authorization: Bearer <key>` on the WebSocket handshake, which the browser WebSocket constructor cannot set. Settings requests optional `<all_urls>` permission, required for Chrome's Declarative Net Request header modification on WebSocket requests. The service worker validates the Bailian URL and YouTube sender, installs a session rule scoped to that exact URL, `websocket` resource type, and current tab, then removes it after the socket opens or the port disconnects. On worker startup, stale rules from this extension's reserved ID range are removed. The key stays in local extension storage and the handshake header; it is never put into the URL or package.

## Connection invariants

- Gemini rotation: 505 seconds by default, configurable from 120 to 580 seconds. Qwen rotation: 120 seconds.
- Qwen planned rotation sends `session.finish`, queues new audio while accepting old-session tail results, and replaces the socket on `session.finished`, close, or a three-second deadline. Stop invalidates all pending callbacks. Automated timers exercise the actual rotation callback rather than only checking stop-time finishing.
- Queue: at most 200 audio chunks, approximately 20 seconds. Drop the oldest when full.
- Abrupt disconnections can prepend the last ten sent chunks, approximately one second.
- Handshake watchdog: 12 seconds. Reconnect delay starts at one second and backs off to 15 seconds.
- Creating a connection cancels old timers, advances its generation, and closes the previous socket.
- Scheduling a reconnect cancels the rotation timer. Stop clears all timers and the current socket.
- No transcript output during silence is normal; it is not a disconnect detector.

Rotation is a reconnect with queued audio, not overlapping seamless connections.

## Whole-video subtitles

The task lives in the content script, like the live session, and is cancelled by navigation, reload, or the user. Everything that finished validation is already in storage, so cancelling loses only in-flight requests. Starting either mode deactivates the other because they share the caption layer.

**Reading the track.** The page bridge runs at `document_start` in the MAIN world and wraps `window.fetch` and `XMLHttpRequest` to record the player's `/api/timedtext` requests and bodies. Since 2025 those requests carry a `pot` parameter; a bare `baseUrl` from the player response returns an empty 200. The bridge first tries everything that does not touch the player, cheapest first: an already-captured `json3` body for the same video, language, and kind; the captured URL refetched with `fmt=json3`; the matching track URL from `player.getAudioTrack().captionTracks`, which usually carries `pot` without any prior request; the track's own `baseUrl` completed with a `pot` from any source plus the `c`, `cplayer`, `xorb`/`xobt`/`xovt`, device (`ytcfg.get('DEVICE')`), and `cver` parameters that read-frog uses; and another captured request for the same video with the track parameters swapped, which works because `lang`, `kind`, and `fmt` are not in `sparams`. Only then does it trigger the player: it turns CC on (`player.toggleSubtitles()` or the CC button) while hiding the native caption container, and after three seconds without activity also selects the track through `setOption`. While waiting it polls every 200 ms but re-runs the candidates only when something changed (a new captured request or new audio-track URLs), and each candidate URL is requested at most once. The whole read has a 20-second deadline (the content script waits 25 seconds), the wait after triggering is capped at 12 seconds, and the last fallback is the bare `baseUrl`, kept as a diagnostic control. CC is restored only when the video and player node are unchanged and CC is still on; if the user turned it off meanwhile it is left alone. Reads are serialized in the bridge, and `KIND_CANCEL` from the content script (sent on cancel or navigation) aborts the current read at its next check. Every step is recorded in `tried` (source, elapsed time, error), which is returned with both success and failure, logged by `readTrack`, and named in the user-facing error text. Auto-translated tracks (`tlang`) are never selected; the player's currently selected track is preferred when it matches the configured source language, and it is the first choice in auto-detect mode. The bridge's own refetches are excluded from capture to avoid loops. This is undocumented YouTube behavior and must be verified in a real browser after YouTube changes.

**Units.** `Json3.parse` flattens events into words with absolute times and skips `aAppend` rolling markers. `Json3.detectFormat` labels the raw events as `standard`, `scrolling-asr`, `karaoke`, or `animated` for logs and `probeCaptions()` only; it does not change parsing, so it does not affect `SEG_VERSION`. For auto captions, `Segmenter.build` groups words by estimated pauses (word end is estimated from character count because `json3` has no word end times), splits over-long or over-long-duration groups at the largest pause near the middle, merges tiny fragments into the next unit, and ends each unit before the next one starts. Manual tracks keep their cues. Ids are sequential from 1; the model never sees times. Changing any segmentation rule requires bumping `LT.SUBS.SEG_VERSION`, which is part of the cache fingerprint and the source-cache validity check.

**Blocks and order.** `Chunker.plan` splits by unit count and character count. Workers pick the block containing the playback position first, then later blocks by distance, then earlier ones. The block containing the position is requested as a head range of `HEAD_UNITS` starting at the position, then the rest, then the part before the position. Each request carries `CONTEXT_UNITS` of surrounding source text as reference only. Displayed text comes straight from the in-memory unit array, so a unit is watchable as soon as its request validated; the "complete" flag only gates zero-request cache hits.

**Validation.** Responses are `id<TAB>text` lines. The whole id set is checked, empty translations count as missing, and extra ids are ignored. A finish reason of length, or a missing suffix, is treated as truncation: only the tail is retranslated, or the range is halved when nothing usable came back. Scattered gaps are topped up with a request for the missing ids; leftover very short units or bracketed tags fall back to the source text. Rate limits set a shared cooldown from `Retry-After` or Gemini's `retryDelay`; 5xx and network errors back off exponentially; 400/401/403/404 are fatal and stop the task.

**Cache.** Keys are `vs:m:<videoId>` (track, target, fingerprints, block bounds, complete flag), `vs:s:<videoId>:<trackKey>` (packed units), and `vs:c:<videoId>:<fp>:<i>` (one array per validated block). The settings-page list is derived from per-video meta records, avoiding a shared read-modify-write index across tabs. The fingerprint covers the segmentation version, source content and timeline, block parameters, track, target language, API type, endpoint, model, and full system prompt. Cached source version, bounds, and non-empty translations are validated before reuse. A usable cache with different translation settings, even if partial, is kept and labeled; restore its original settings to resume or explicitly retranslate. Invalid source data is read again and cannot reuse old numbered translations. Complete caches do not require credentials to load. Late writes may finish saving the old video's data but must never mutate the new task's state or status text.

**Network.** `Net.request` (and its `Net.post` shorthand) first tries a direct `fetch` with the requested method, with an automatic service-worker fallback only for a network failure before receiving a response. A broken response stream must not be mistaken for CORS rejection. A two-minute deadline covers the entire request, including its body, unless the caller passes a shorter `timeoutMs`; timeout is retryable, while user cancellation is not. Completion releases abort listeners and stream reader locks. The service worker checks the origin's host permission, relays chunks with the requested method (GET and HEAD carry no body), and aborts when the port closes. Port messages count as worker activity, but a provider that stays silent can still outlast the worker's idle lifetime; streaming alone is not a lifetime guarantee. Custom domains are granted from Settings through `optional_host_permissions`.

**Text-model configuration.** Endpoints are stored as a list of provider configurations (`settings.providers`; each carries its own concurrency and request path). `subsProviderId` selects the whole-video subtitle model, while `liveContextProviderId` independently selects the context model; `TextModel.resolve(settings, providerId)` picks the explicit configuration. Older settings without a context id initially retain their existing subtitle choice; subsequent changes are independent. Both uses accept OpenAI-compatible `chat/completions` and Gemini `generateContent`. New installations and new configurations default to OpenAI-compatible format, while existing configurations retain their explicit API type. `normalize()` clamps ranges, removes duplicate ids, and guarantees at least one configuration. The Settings page offers two checks per configuration: `TextModel.probe` queries model metadata (Gemini) or the model list (OpenAI-compatible) over GET and proves only that the key can reach the query endpoint and that the model name exists, while `TextModel.generateTest` sends one tiny request through `translate`, so it exercises streaming, SSE parsing, and routing at a small quota cost. `TextModel.listModels` feeds the model-name picker from the account's own list; nothing is pre-filled.

**Caption bridge safeguards.** A captured body must contain actual `json3` text events, not just begin with a JSON brace. Each refetch has a 3.5-second deadline and the whole read a 20-second one. Navigation or cancellation stops further attempts, and the temporary CC change is restored only while the original video and player are still current and CC is still on. Simulated bridge tests cover the capture, audio-track, composed-URL, trigger, user-intervention, deadline, dedupe, cancel, and navigation paths; they do not prove current YouTube endpoint compatibility.

For a browser check, run `await LT.debug.probeCaptions()` first in the content-script console context: it reads and segments the chosen track without calling a model or writing cache and returns the track list, the player's selected track, whether a `pot` is available, the source that worked, the `tried` log, the detected format, and sample units. `LT.debug.videoSubs` exposes the controller and `LT.debug.startVideoSubs(force)` starts a task; `LT.debug.videoSubs.status()` shows requests made, which should be zero on a cache hit. The outstanding real-world validation is reading a real caption track (manual, auto, and multi-language), translating at least one replay longer than an hour with the selected model, checking playback sync at the start, middle, and end, and confirming behavior across popup close, video switching, tab close, and browser restart.

## YouTube chat and comments

`enableChatTranslation` and `enableCommentTranslation` are independent, false by default, and share the source/target language settings. They run without an audio or whole-video subtitle session. Their results remain in page memory; they do not use subtitle persistence or the live event logger. Changing their switches or caption appearance does not invalidate an otherwise matching live-context preview.

**Chat.** A small isolated-world content script runs at `document_idle` in matching `www.youtube.com/live_chat*` frames, including embedded chat and chat replay. The heavier subtitle scripts exclude those URLs, avoiding duplicate initialization on pop-out chat pages. The script detects Chrome's `Translator` and, for automatic source language, `LanguageDetector`. Chat status and preparation now live in the extension popup; the script no longer inserts a control bar above YouTube chat. The popup starts any required model downloads from its own user-activated click and then asks the chat frame to create its translator. There is no paid-model fallback. Chrome documents the APIs for desktop windows and same-origin frames: [Translator API](https://developer.chrome.com/docs/ai/translator-api). Actual exposure in the user's content-script realm, model downloads across the popup/frame boundary, policy, and YouTube frame layout must still be checked in Chrome.

Chat observes text, paid-message, and membership renderers that contain `#message`. It keeps at most 30 queued messages, processes them sequentially, skips pure emoji, messages over 2,000 characters, and rows no longer visible/current, and remembers at most 500 translation results. Each result is a text-only block span appended inside `#message`, preserving original nodes and inheriting message color, including paid/membership backgrounds. It matches the source font metrics rather than forcing a smaller/dimmer result. `YouTubeText.readText` reads only original nodes, excludes injected `.lt-yt-text` content, and retains line breaks, link text, and Unicode emoji alternatives while excluding custom image-emote names and hover tooltips. The span carries target `lang`, automatic direction, and `translate="no"`. Repainted original content can regain a result from cache. Scroll follows only when already near the bottom. Stop, language changes, frame video-id changes, or page exit advance a generation, abort outstanding work, and destroy model instances. Recycled message nodes lose stale translations. The worker forwards compact chat status to the top frame and can ask existing chat frames to republish if the top script missed initial status; it does not retain chat text or state.

**Comments.** The main-page module decorates already-loaded `#comments #content-text` nodes and watches later comments or expanded replies. Individual clicks or the viewport action enqueue work; it does not fetch more comments or translate merely because the switch was enabled. Each batch is at most eight entries and 6,000 source characters, with a 6,000-character single-comment limit. Each request freezes the selected subtitle provider, language, and background. The model receives `{id,text,parent}` JSON; the parent is reference only. Selected comment text, reply parent text, enabled metadata/manual background, and non-stale same-page prepared terms may be sent to the configured subtitle endpoint. No new context-generation request is made. The complete returned numbered set must validate before new results are cached or shown. A failed batch stops subsequent queued requests for manual retry.

Comment cancellation and settings/navigation changes abort request controllers and invalidate generations. Results additionally require the current video, source node/text, and associated result host to match, so stale replies cannot change a replacement entry. Completed translations are reused only in a bounded, 300-entry page-memory cache keyed by source/parent text, full prompt, and endpoint/model identity. Disabling or changing configuration removes rendered results; stopping a batch keeps completed results. Output uses `textContent`, with no model-generated HTML inserted. Comments reuse `TextModel.translate` and its two-minute whole-response deadline and relay path.

**Bilingual layout.** Comment hosts follow the nearest `ytd-text-inline-expander`, `ytd-expander`, or `#expander`, keeping results outside the original's clipped/collapsed text box. The result comes first, then compact retranslate and hide/show buttons; successful results carry no extra language label or decorative border. Source font metrics are copied because the source can use a different size from the surrounding comment container, especially for replies. The display approach was reviewed against [KISS Translator's wrapper insertion](https://github.com/fishjar/kiss-translator/blob/dev/src/libs/translator.js) and [Read Frog's inline/block insertion](https://github.com/mengxi-ream/read-frog/blob/main/src/utils/host/translate/dom/translation-insertion.ts); the extension implements its own narrow YouTube layout rather than importing either runtime.

**Chat reaction filtering.** Before enqueueing or language detection, `YouTubeText.shouldTranslateChat` checks the original's text without image-emote alternatives. It normalizes full-width characters and case, ignores punctuation/emoji, and skips messages consisting only of emoji/symbols, numbers, laughter (`www`, repeated `草`/`笑`), or common short reactions (KAWAII, LOL, NT, NICE, GG, GGWP, WP, LMAO, ROFL, XD, ORZ). Combinations of those tokens also skip. Matching applies to the entire message, so words, numbers, and `草` within substantive sentences do not suppress translation. Native message content remains visible; filtering neither removes messages nor adds a skip indicator.

**Interface themes (0.3.4).** `ui.css` provides shared light and neutral-gray dark tokens. `theme.js` resolves `uiTheme` (`system` by default, `light`, or `dark`), reacts to system and local storage changes, and protects a pending manual choice from late initial reads and earlier storage events. Settings saves run serially; only the latest theme revision can finish the manual preview. Settings expose the preference under General; the popup has a theme toggle. The popup root and body have an explicit 420 px intrinsic width, without a viewport-based maximum that can shrink Chrome's auto-sized action popup. Rounded groups, native checkbox switches, grouped navigation, and idle diagnostics hiding are retained. Caption/message styles remain page-aware. Translation-style webpage previews keep their own independent light/dark selection.

Source text extraction ignores image alt names unless they consist of Unicode emoji, and excludes `tp-yt-paper-tooltip`, `yt-tooltip-renderer`, and elements with `role="tooltip"`. Custom emote names and membership labels are never sent as message text. Inserting a hover tooltip therefore leaves the source/cache identity unchanged; the original images and native tooltips remain in YouTube's DOM.

**Comment color scope (0.3.5).** Injected comment results sit outside the expander and cannot assume its sibling inherits the source color. YouTube can style an inner `.yt-core-attributed-string` while its outer wrapper/body stays black. `YouTubeText.applySourceColor` reads that node (or the source node when no inner node exists) and stores the computed foreground on the plugin host. Root `dark`/class/style changes schedule a color rescan without replacing text, expanding hidden results, or requesting a model. Controls/status/focus/disabled states use their own light/dark tokens keyed to YouTube's `html[dark]`, independently of the popup theme and custom translation decoration.

The revised offline fixture deliberately leaves the body and comment-scope variables black while native source inner nodes have their proper theme colors. The 0.3.4 unpacked runtime fails the source/result-color comparison; 0.3.5 passes for both themes and 1440/390 px, including theme changes with no DOM text repaint or extra requests. All 101 simulated regressions pass; current user Chrome and actual YouTube DOM remain unverified.

## Selection translation and Japanese/English speech (0.4.0)

`contextMenus` exposes one **翻译与朗读** selection action. The menu handler freezes `selectionText`, injects constants/settings/selection/UI only after the user action using `activeTab` and `scripting`, and targets the exact `frameId`. There is no new permanent all-site content script. If a selected frame cannot be injected, retry in the same tab's top frame and anchor beside its iframe. No extra page/window or selection storage is used; browser-internal pages that prohibit injection receive an action badge/title explaining the restriction.

`Selection.language` classifies a NFKC-normalized copy: at least one letter, all in Script=Latin, means `en-US`; everything else means `ja-JP`. Spaces/numbers/punctuation/emoji do not affect this rule. Original text is not rewritten; blank or over-4,000-character requests fail locally. Selection translation resolves the existing subtitle provider/target language and reuses `TextModel`/`Net` in the worker, without video background or a preliminary LLM request.

Speech adapters freeze provider credentials, model, voice, text and language. Microsoft uses an attributed Read Frog-derived consumer endpoint/signature and ordinary Neural voices, with a short-lived token and one 401/403 refresh. Gemini uses an explicit `speechConfig.languageCode`; legacy 3.1 requests use `prebuiltVoiceConfig.voiceName` and newer 3.8 requests use `voiceConfig.voice` with speech metadata. Parse each MIME type: raw PCM16LE becomes a mono WAV with the reported rate, while WAV/MP3 remain unchanged. Abort signals and deadlines cover complete response bodies. HTTP errors do not expose response bodies or keys.

The worker serializes player commands and coalesces offscreen creation. One owner/request identity is active globally; start, stop, configuration change, port disconnect and tab navigation invalidate it. Recheck identity after asynchronous settings, hash, synthesis and document creation. Ports send a ten-second ping while connected, and the offscreen player sends a ten-second heartbeat while playing; these messages prevent MV3 idle shutdown during user-visible work. `AUDIO_PLAYBACK` documents can disappear after inactivity, so the next playback recreates them. Monotonic command identities reject late stops/plays. Stop/end/error pause and unload Audio, clear callbacks/heartbeats and revoke object URLs. Playback rate preserves pitch.

Up to three clips are held in worker memory; their replay validity is ten minutes. The identity hashes the frozen configuration (including credentials) plus language/text, without plaintext credentials in the key. Configuration changes clear the cache. No selected text/audio is saved to disk or live logs. `ttsGeminiApiKey` is redacted by live-log helpers, excluded from default settings exports and retained when importing an export without keys or restoring defaults with “keep keys”. All API keys still use unencrypted `chrome.storage.local`.

The floating panel uses Shadow DOM, constructed stylesheets and textContent, follows the extension's soft gray theme including live theme changes, and offers original/translation with manual playback. Its compact layout limits the original-text height and gives translated text its own scroll area; idle actions are hidden. Opening runs translation only; synthesis starts when the user clicks play. Clone the selection Range before focusing the panel and position next to its rectangle, choosing below/above and clamping inside the viewport. The header supports pointer dragging. Before a drag, ResizeObserver and scroll/resize listeners keep it beside the selection; after a drag, they only clamp the manually chosen position inside the viewport, including fullscreen changes. Closing releases these listeners, disconnects the port and cancels owned work. Settings previews use the same synthesis/player path; changing fields or stopping during a pending settings save also invalidates the preview request. Speech playback is in the extension's offscreen document; AudioTap continues to read only the YouTube video element, never microphone/system-output capture.

Verification distinguishes upstream from substitutes. All 118 simulated regressions pass after the player/chat/selection UI update. Isolated Chromium tested real Microsoft Japanese/English synthesis/playback, dark/light and 1440/390 px layout, cancel/replay/navigation, and network-substitute Gemini/selection translation. A real YouTube watch page in an isolated Chromium profile confirmed the player buttons mount inside `.ytp-right-controls`; fixture clicks confirmed the buttons do not trigger player playback. A real AudioTap worklet captured an injected tone, then remained silent while offscreen speech played with a silent video. The player recreates a closed offscreen document. Selection checks confirm the panel sits beside a real DOM Range, stays inside narrow viewports, waits for a playback click, and retains its dragged position when translation grows and the page scrolls. Current user Chrome integration, actual live/whole-video actions, real Gemini TTS access and subjective voice quality remain unverified. See the [implementation plan/status](selection-and-japanese-tts-plan.md) and [GPL provenance](third-party-tts.md).

## Checks and packaging

Use Node.js 22+:

```sh
npm run check
npm run package
git diff --check
```

No dependency installation is needed. The package script writes a deterministic, uncompressed ZIP using the standard ZIP format. It includes only `manifest.json`, `src/`, and `icons/`; it excludes test fixtures, docs, Git metadata, and any local settings.

GitHub Actions also checks ZIP integrity and uploads the archive as a workflow artifact. A release ZIP can be extracted into a permanent directory and loaded unpacked.

For a browser check, reload the extension and then refresh YouTube. In DevTools, select the extension's content-script execution context before using `LT.debug.start()`, `LT.debug.stop()`, `LT.debug.status()`, or `LT.debug.videoSubs`. The page's default MAIN world does not expose that object. Never paste API keys or private notes into public diagnostics.

The remaining real-world validation is a live-stream soak test covering multiple rotations for each provider, a network interruption, and video navigation, plus the whole-video checks listed above. The automated tests exercise state transitions using mocks; they do not establish upstream availability, caption-endpoint behavior, or translation quality.
